# 2026년 10월 보안 점검 — 반영 내역

2026-11-01에 받은 「Ouryn 지갑 보안·사용성·출시 준비도 점검 보고서」(10월까지의 앱 기준, F01~F20)를 `security/2026-10-review` 브랜치에 반영한 기록입니다. 보고서 원문은 작성자 로컬 경로 등이 들어 있어 저장소에 넣지 않았습니다.

## 검증 상태 — 먼저 읽어주세요

- 이 반영 작업은 **Swift 컴파일러가 없는 환경**에서 했습니다. Xcode 빌드, 시뮬레이터·실기기 실행은 아직 하지 않았습니다.
- 확인한 것: 바꾼 Swift 파일 전부 구문 분석(tree-sitter) 오류 없음, ERC-681 수량 변환 로직을 별도 구현으로 교차 확인.
- 머지 전에 Mac에서 할 일:
  1. Debug·Release 빌드 (앱 + 위젯)
  2. `python3 ios/Tests/check_scan.py` — QR 해석(ERC-681 포함)·스캔 전환 회귀 검사
  3. `python3 ios/Tests/check_pin_policy.py` — PIN 10회 잠금·시계 조작 회귀 검사
  4. 기존 `check_pin.py`·`check_startup.py`·`check_p1.py`·`check_quiz.py`
  5. DEBUG 진단(`--multichain-diagnostics`) — ERC-681 항목 10개를 새로 넣었습니다
  6. 아래 '실기기 확인' 목록

## 동작이 바뀐 점 (사용자에게 보이는 것)

- '보낼 때 비밀번호도 확인'은 실제 서명 경로에 연결된 **새 설정(기본 꺼짐)**입니다. 켜면 보낼 때 PIN과 Face ID를 모두 묻고, 끄려면 PIN이 필요합니다. (처음에는 예전 설정값을 그대로 이어 써서 모든 사용자에게 기본으로 켜졌는데, 매번 PIN을 묻는 불편이 커서 [UX 점검](ux-review-2026-11.md) 때 선택 사항으로 바꿨습니다)
- 비트코인·이더리움·맨틀 송금은 블록이 더 쌓일 때까지 '확인 중'으로 남습니다(이더리움 약 2~3분, 비트코인 약 30분). 블록에 들어간 뒤에는 같은 네트워크로 다음 송금을 할 수 있습니다.
- 비트코인 입금은 블록에 들어가기 전에는 잔액에 더하지 않고, 코인 화면·받기 화면에 '확인 중인 입금'으로 따로 보여줍니다.
- 12단어를 적지 않은 지갑으로 받기를 열면 안내 화면이 먼저 나옵니다.
- 지금 통장의 내 주소로는 보낼 수 없습니다(전에도 서버 견적 단계에서 막혔고, 이제 입력 단계에서 알림).

## 실기기 확인 (머지 전 권장)

- Face ID: 등록 그대로/추가 등록/잠금 화면을 띄운 채 새 얼굴 등록 후 복귀/생체인증 잠김
- PIN 5·10회 실패 → 대기·hard lock → 비밀번호 바꾸기 차단 → Face ID 또는 12단어로 다시 정하기
- 날짜를 앞으로 돌린 뒤 대기 시간 유지, 재부팅 뒤 대기
- 복구 문구 화면·온보딩 12단어 화면에서 앱 전환·알림 센터·전화·기기 잠금
- 앱 잠금: 60초 안에 기기 잠금 후 복귀
- ERC-681 QR: MetaMask 등에서 만든 USDC 요청 QR 스캔 → 받는 사람·수량 확인
- 테스트넷 송금(이더리움 Sepolia·비트코인 testnet4): 확정 깊이 도달 전 '확인 중', 도달 뒤 완료
- 생체인증 없는 폰(또는 시뮬레이터)에서 새 지갑 만들기·되찾기
